**Coherent review paths.** Review the following connected stories, using already accepted terms as anchors:

- **Initial setup and continuity:** Project and native Workspace → Onboarding → scoped Readiness Report / Build Readiness → explicit user Spawn → Launch Readiness and saved Handover → representative Initial Verification Work / Operational Verification. Handover supplies continuity information; Checkpoint is saved execution state; neither creates authority. Optional integrations do not block unrelated build work.
- **Responsibility, method and authority:** Agent Role → Agent Procedure → Entry Skill / Result Contract; Agent Definition references native profiles and selected named/sourced Skills. Orchestrator Responsibility survives replacement of its Session Binding. Capability, Authority, action Permission, Effective Authority and shared Resource Limit remain distinct. Principle Selection cannot disable Core Operating Rules. Configuration Revision, Effective Configuration, Pinned Revision and Source Drift explain historical work without implying immutable external Skills or isolation.
- **Execution:** Workflow Definition → Run-specific Execution Plan → Workflow Step → Step Run → admitted Attempt. Five patterns compose recursively; code owns invariants and bounded agent decisions occur within them. Stop Condition does not mean pass. Keep accepted D02/D03 identity, join, aggregate Outcome, evidence and reuse rules intact.
- **Automation and technical effects:** Trigger / source binding → Schedule Occurrence or Source Event → Code Job Handler / source progress → Work Delivery and declared-stage Receipt → work execution. Occurrence, Job Run and Workflow Run differ; an unchanged poll need not invoke an agent. Run Timer concerns existing work. Tracked Operation, intent, journal and reconciliation explain uncertain effects without becoming business requests or exactly-once guarantees.
- **Improvement and evidence:** Feedback / Hypothesis / Experiment → Candidate → Check Plan / Check Result and comparable Evaluation Trials → independent authorized activation or upstream contribution. Dataset identifies frozen inputs; Suite groups cases and assessment arrangements; Case is the task/input situation; Environment captures relevant conditions; grader is the assessment mechanism, not the final Verdict. Regression requires supported deterioration. Fix-forward, compatible independent Recovery and traceable/shared/unmeasured cost policy remain approved.

**Name collisions and real contradictions.** Proposed qualifications include **Orchestrator Session Binding**, **Orchestrator Responsibility**, **Agent Procedure**, **Work Delivery**, **Source Cursor**, **Code Job Handler**, **Paseo Cadence**, **Tracked Operation** and **Execution Admission**. They distinguish the local meanings without demanding new records. Bare Binding also names role-to-definition configuration and authenticated context association; Role is responsibility rather than a caller-supplied privilege; Owner can mean responsibility, data owner or authenticated principal. Ready must name its stage; being loaded/active or technically capable is not verified task competence. Source must be qualified as project-requirement authority, Skill provenance, activation source, or evidence origin. There is no proposed universal Binding, Role, Owner, Ready or Source entity.

Existing conflicts need editorial reconciliation, not product re-decisions: first-run text still says menu naming is open although UI entries confirm it; architecture shorthand implies harness-managed model settings while configuration requires native references; CodeJobSpec omits once/bounded-parallel/bounded-catch-up options required by scope; generic MCP optionality predates its concrete mandatory onboarding caller. Older new-repository examples and unrestricted known-good rollback language do not override current V1 scope or current-data recovery compatibility.

**Graph caveats.** The register contains 202 inferred, 18 approved and 10 proposed relations. Proposed does not mean entailed, and inferred does not mean approved. R164/R165's Experiment links go beyond SRC202's mere inventory; do not infer a required Experiment aggregate. R222/R223's Suite/Case containment and input linkage are modeling proposals, not specified identities/cardinalities. R132 narrows a trigger-binding target to Job despite modules.md:27 permitting handler/program/inbox/responsibility. R099 must be conditional on an agent-dispatching step. R143 must not equate request idempotency with native effect correlation. R180/R181 do not establish that a Check Plan independently chooses release policy. R024's “establishes” requires successful evidence, not merely task selection. R070 must not turn every enduring project rule into a tracked Work Item by fiat.

Pattern-as-value versus composable structure, Configuration Revision as value, Pinned Revision as role, and records typed artifact/state are editorial graph classifications, not accepted storage or lifecycle requirements. The manifest's relatedConceptIds are navigation aids, not new asserted edges. Grader has no concept ID here: retain its contextual assessment meaning; do not invent a missing entity to satisfy a diagram.

**Material decisions and next interview frontier.** **Zero new material meaning decisions** were found; every unresolvedQuestion is null. There are 52 source-backed normalizations, 21 naming choices and 23 external general terms. The latter remain in inventory with contextual definitions and an owner for the note; they need not become standalone domain entries. The next frontier is grouped D01 acceptance, beginning with continuity/responsibility/authority and the Procedure–Skill–contract boundary, then reviewing execution, automation and evaluation paths. Ask the user only about a concrete disagreement that changes meaning; source synthesis, API investigation and schema choices remain our work. Do not reopen UI translations or D02–D05.

**Migration after acceptance.** Record only accepted concise definitions at the owning location; existing files are documentation ownership, not seven automatic services, databases or bounded contexts. Keep concept IDs stable, retain existing Vietnamese anchors/source names and register aliases, and add English anchors alongside them when approved. Keep confirmed UI labels scoped: Workflow as a mode is not a global synonym for its domain counterpart. Prior proposed names can remain trace aliases only with their draft provenance. External general terms should receive contextual references rather than automatic new headers. Repoint dependent links/mappings deliberately; preserve old pinned excerpts and revision history, appending new source records for accepted text instead of silently rewriting historical pins. Regeneration and implementation belong to a later authorized step.
