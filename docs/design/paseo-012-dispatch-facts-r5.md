## Create identities and crash boundaries

**Contract/read:** modern SDK creation uses the server lifecycle service. Its namespace is `(kind, idempotencyKey)` within one `paseoHome/creations`, across socket lifetimes—not per caller/project/workspace. The server hashes canonicalized request intent, excluding transport request ID/type/subscription/key; changed intent conflicts. The SDK generates a key when omitted and keeps only an in-memory operation map, lost on plugin/client restart. Modern creation accepts an initial prompt; legacy keyed `create_agent_request` rejects it. [C1–C4]

Before provisioning, the service persists a selected/generated agent UUID; exclusive `.claim` files reject another creation identity claiming that ID or an already-existing resource. Thus `agentId` is an enforced resource identity, not another replay key. Completed replay validates resource existence; deletion does not authorize recreation. `clientMessageId` correlates the initial prompt; it supplies no independent create/prompt execution dedupe. Changing it changes keyed intent. [C1–C5, M1]

Milestones persist `inFlight` before agent/prompt effects. Lost responses can recover completed records. Restart with an unfinished stage produces `failed/outcomeUnknown`, without repeating that stage; failures classified as known-before-registration can retry the same IDs. No TTL/GC is implemented in these receipt/claim owners; that is not an eternal-retention guarantee. Atomic replacement uses write+rename, without fsync; cross-process fencing/power-loss durability are unproven. [C1–C3, F]

## Send acknowledgement and correlation

**Contract/read:** SDK `send()` creates a random `messageId` unless supplied. For a nonempty ID, the RPC receipt namespace is `(resolved agentId, messageId)` under `agent-requests`; its fingerprint covers prompt/images/attachments, source agent and normalized active-turn behavior. Same completed request returns without sending; changed payload conflicts; persisted `pending` returns `agent_request_outcome_unknown`, including after dispatch errors. Calls with missing/empty wire IDs bypass this receipt. This owner also implements no TTL/GC. [S1–S3]

Ordering is pending receipt → dispatch → completed receipt → `accepted:true`. Ordinary new-Turn dispatch waits for manager run-start; steering waits for provider-adapter acceptance; out-of-band commands need no Turn. Claude steering acceptance means insertion into its live SDK input (`priority:"next"`), not consumption. Neither response nor `turn_started` proves task processing/result acknowledgement. There is no shared durable “enqueued/delivered/processed” state machine. A crash before dispatch or after dispatch acceptance but before completion leaves the same ambiguous pending receipt; after completion, response loss permits deduped replay. An error/`accepted:false` alone therefore does not prove non-delivery. [S1–S4, B2]

Receipts store only fingerprint/state/agent ID, without Turn ID or provider acknowledgement; the inspected public SDK has no receipt-query method. Manager timeline rows correlate client/provider message IDs and Turn IDs, but rejected human prompts also remain visible. Critically, normal daemon bootstrap does **not** wire the optional durable timeline store; live rows are in memory, and provider-history hydration does not preserve row Turn metadata. Agent-originated envelopes can reconstruct message identity when retained in history; ordinary prompt correlation is provider-dependent. No universal durable message→Turn mapping is established. [M1–M4]

## Busy delivery and permission waits

**Contract/read:** SDK/RPC offers only `interrupt` and `steer`; omission means interrupt: cancel the running Turn and start a replacement. Steer joins an active Turn when supported, otherwise falls back to replacement; explicit errors propagate. Native MCP `send_agent_prompt` defaults to steer for agent callers, interrupt otherwise, and exposes no caller `messageId` receipt. [S2–S4, B1, B4]

Steer admission captures an expected Turn, serializes foreground mutations, drains/buffers events and rejects stale fallback rather than replacing a later Turn. Claude captures/checks the live stream without an intervening await; Codex checks captured identity across awaits, sends native `expectedTurnId`, and validates acknowledgement. This guard is internal: public send has no caller-supplied expected-Turn/idle CAS. A human Turn starting after an idle observation but before admission can receive the wake. [B1–B3, P]

The app additionally offers **Queue**, defaulting its setting to **steer**. Queue is an app-session memory map, not a daemon/SDK queue contract. It drains the first item after stopped-running, removes before send/restores on error, and submits using steer with a newly generated dispatch message ID. App Queue becomes interrupt when permission is pending. SDK RPC sends always request permission clearing; Claude denies superseded pending permissions, and Codex denies them after steer acceptance. Native MCP does not request that clearing. Sending is therefore not a passive wake during permission wait. [Q1–Q3, S2, B4, B5]

## Observation and concurrency limits

**Contract/read:** creation `onEvent`/creation subscription exposes persisted lifecycle snapshots. Public agent APIs provide paginated listing, owned list subscriptions, refresh, status/active-Turn/pending-permission snapshots, and timeline subscriptions/refetch. Establish timeline `.ready`; reconnect restores live delivery, not missed history. Refetch using epoch/sequence pagination and handle replacement/reset/gap. Hooks cover Turn/permission/archive/close events, but invocation is asynchronous, overlapping and unreplayed. Stored unloaded-agent projections omit active Turn and return empty permissions. [C4, O1–O4]

**Inference/gap:** these observations can trigger coalesced reconciliation; they do not atomically reserve an idle Session against concurrent human chat. `run()` sends then waits by agent ID; `waitForFinish` is not message/Assignment-bound. Idle/canceled/permission/timeout cannot substitute for delivery/result acknowledgement or establish logical Pause/human Stop attribution. No exactly-once or universal provider proof follows. [O1–O4, B1]

## Actionable contract probes — proposed, not run

1. Drop create responses/restart at each intent, claim, registration and prompt milestone; replay identical/changed keys and UUIDs across clients/workspaces and deletion.
2. Drop send responses/crash before dispatch, after acceptance and after receipt completion; replay identical ID/payload and conflict variants; distinguish missing evidence from rejection.
3. Record message/provider/Turn correlation before and after restart/history replacement for each supported provider and agent-originated envelope.
4. Race human Turn B against idle wake, steering A, unavailable fallback and run/wait; establish which message/Turn each observation proves.
5. Exercise steer/interrupt/Queue during tool/question/plan permission waits, app restart, disconnect and unsupported steering; verify denials, queue retention and uncertainty without automatic redispatch.
