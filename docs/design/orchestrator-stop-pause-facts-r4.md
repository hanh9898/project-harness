## Native Stop and interrupting sends

**Read, pinned source:** the composer Stop button and `agent.interrupt` keyboard action reach `handleCancelAgent`, then `cancelComposerAgent`, which calls `client.cancelAgent(agentId)`. The composer records local cancellation presentation through `beginAgentCancellation`/`settleAgentCancellation`; this is not a plugin stop-intent receipt. [Composer](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/app/src/composer/index.tsx#L1875), [action](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/app/src/composer/actions.ts#L177).

**Read:** CLI agent Stop calls the same client cancellation method, skipping snapshots not marked `running`; MCP `cancel_agent` invokes the shared `cancelAgentRunCommand`. Cancellation keeps the agent alive, unlike kill/archive. [CLI source](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/cli/src/commands/agent/stop.ts#L84), [MCP source](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/tools/paseo-tools.ts#L2170), [official MCP semantics](https://paseo.sh/docs/mcp#agents).

**Read:** sending with `activeTurnBehavior: "interrupt"` replaces an active Turn with another prompt. Agent-originated MCP/CLI sends default to `steer`; other callers default to `interrupt`; unavailable steering falls back to interruption. Consequently a cancellation can accompany continued conversation rather than an intention to remain stopped. [CLI send contract](https://paseo.sh/docs/cli#sending-messages), [dispatch source](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/agent-prompt.ts).

## Observable outcomes do not identify the human

**Read, 0.11.1:** lifecycle statuses are `initializing`, `idle`, `running`, `error`, `closed`. Stream events include `turn_completed`, `turn_failed`, `turn_canceled`; their fields include provider and optional `turnId`, with error/code/diagnostic for failure or a string `reason` for cancellation. Plugin `agent.turn_ended` carries agent, nullable `turnId`, timeline and completed/failed/canceled outcome. These inspected shapes contain no initiator, human-action flag or cancel-request correlation. [Protocol declarations](../../spikes/paseo-contract/node_modules/@getpaseo/protocol/dist/agent-types.d.ts), [plugin declarations](../../spikes/paseo-contract/node_modules/@getpaseo/plugin/dist/server/lifecycle.d.ts).

**Read, pinned source:** `cancel_agent_request` carries `agentId` and optional `requestId`; the requesting connection receives a corresponding response. That request identity is not forwarded into the terminal hook. Reload, rewind and prompt replacement also use cancellation. The manager can synthesize cancellation reason `interrupted` after settlement timeout. Codex maps an interrupted result to `interrupted`; Claude's foreground cancel path uses `Interrupted`. These strings describe paths, not authenticated human intent. [Request/response handler](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/session.ts#L4687), [manager](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/agent-manager.ts#L3128), [Codex](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L6162), [Claude](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/claude/agent.ts#L2450).

**Inference:** even a correlated canceled Turn cannot universally establish who stopped it. Failed/completed outcomes cannot establish the absence of a racing Stop. Idle alone is insufficient. No native Stop interception registration was found in the inspected public plugin declarations; this is a bounded finding, not a universal event inventory.

## Handles, acknowledgement and recovery

**Read:** 0.11.1 `PaseoAgentHandle` exposes send/run/wait/refresh/archive but no stop/cancel method. Lower-level `DaemonClient.cancelAgent()` sends the cancellation RPC and checks its response. The provider `AgentSession.interrupt()` interface promises settlement of preceding foreground Turns, with idle a no-op; the manager can report `not_running`, `settled`, or `refused`. These are runtime contracts, not proof of external-effect rollback. [Local SDK](../../spikes/paseo-contract/node_modules/@getpaseo/client/dist/index.d.ts), [low-level implementation](../../spikes/paseo-contract/node_modules/@getpaseo/client/dist/daemon-client.js), [provider interface](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/agent-sdk-types.ts#L691).

**Read, current docs:** wait timeout does not cancel the agent. Lifecycle hooks have best-effort live delivery, no persistence/replay/automatic retry, and overlapping callbacks. SDK subscriptions restore after reconnect without replaying missed events; explicit timeline pagination is separate. A transcript/history refetch therefore does not establish recovery of missed, attributed Stop intent. Pinned manager code records timeline items separately from terminal stream dispatch. [Wait behavior](https://paseo.sh/docs/sdk/agents), [hook delivery](https://paseo.sh/docs/plugins/reference#context-and-cleanup), [SDK reconnect](https://paseo.sh/docs/sdk/events), [dispatch](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/agent-manager.ts#L4341).

## Automation and the stop/idle race

**Read:** the inspected cancellation command does not update schedules, heartbeats or harness Work admission. Schedule pause/resume and heartbeat deletion have separate interfaces. The pinned heartbeat target path rejects an already active run, but can start a prompt once idle; no manual-stop latch appears in that path. [Lifecycle command](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/lifecycle-command.ts#L58), [schedule execution](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/schedule/service.ts#L945), [automation interfaces](https://paseo.sh/docs/mcp#schedules-and-heartbeats).

**Read:** native client stopped-running transitions invoke queued-message draining when a queue exists; the inspected Stop action does not clear that queue. Cancellation requests identify an agent, not an expected Turn. Although the manager serializes some foreground mutations, that supplies no shared ordering with a harness admission transaction. [Queue drain](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/app/src/runtime/host-runtime.ts#L2396), [transition callback](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/app/src/runtime/directory-sync/agent-replica.ts#L213).

**Inference:** a wake admitted around cancellation/idle may start another Turn before a delayed hook is processed. Preserving/coalescing A07 events does not itself close this race. **Gaps:** durable native user-intent attribution, correlation across reconnect/reload, ordering with queued sends/heartbeats/Work admission, and provider-specific settlement proof. The inspected contracts support observing termination and acknowledging a requested cancellation; they do not support a universal “native Stop prevents automatic wake until manual resume” promise. Whether that promise is desired remains the later product choice.
