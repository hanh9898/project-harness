## 1. Per-agent MCP materialization, storage and reconnect

**Read:** HTTP/SSE `mcpServers` entries contain `url`, string-valued `headers` and optional `alwaysLoad`; `env` belongs to stdio. The public union has no HTTP secret/environment-reference field ([agent-types.ts:18–63](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/protocol/src/agent-types.ts#L18)).

Claude copies URL/headers into SDK options; Codex maps them to `url`/`http_headers` under per-thread `config.mcp_servers`. Both pass stdio `env` directly. These adapters perform no URL/header environment interpolation or conversion to Codex `env_http_headers`/`bearer_token_env_var` ([Claude mapping](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/claude/agent.ts#L1062), [Codex mapping](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L873), [Codex configuration](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L5350)). **Gap:** downstream native-client interpolation and HTTP authentication behavior were not established.

**Read:** custom MCP config is copied into serializable agent config and written as JSON, without credential substitution/encryption. Thus literal header/stdio-env secrets there persist ([agent-projections.ts:297–330](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/agent-projections.ts#L297), [agent-storage.ts:187](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/agent-storage.ts#L187), [atomic-file.ts](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/atomic-file.ts#L23)). Session-open environment overrides are separately nonpersistent ([reference:817–836](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/public-docs/plugins/reference.md#L817)); that does not create HTTP-header indirection.

Claude's option summary logs MCP names/environment counts, but SDK stderr is logged verbatim. Codex logs malformed stdout lines and, at trace level, raw inbound events. Logger redaction covers specific authorization-header paths, not arbitrary nested values/strings ([Claude summary](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/claude/agent.ts#L593), [stderr](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/claude/agent.ts#L3547), [Codex transport](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/codex/app-server-transport.ts#L354), [redaction](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/logger.ts#L49)). **Gap:** no end-to-end secrecy guarantee or observed credential leak.

Plugin stdout/stderr also enters a retained in-memory tail and persistent daemon log; the reference explicitly prohibits logging credentials ([backend logging](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/public-docs/plugins/reference.md#L2182)).

Resume/reload rebuilds provider launch configuration; Codex supplies MCP config on `thread/resume`; Claude builds options with its native resume ID ([manager resume](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/agent-manager.ts#L1392), [reload](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/agent-manager.ts#L1547), [Codex resume](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/codex-app-server-agent.ts#L4064), [Claude options](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/providers/claude/agent.ts#L3521)). **Gap:** plugin endpoint restart detection, retry timing, credential rotation/rebinding and in-flight outcome recovery. The session-open hook transforms environment, not MCP configuration.

## 2. Host RPC authorization and caller evidence

**Read:** `plugin.rpc.invoke.request` requires `daemon.manage`; Session authorization rejects unauthorized messages before dispatch. The request carries request/plugin/method/input, and dispatch forwards plugin/method/input only ([permission map](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/authorization/operation-permissions.ts#L127), [gate](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/session.ts#L2140), [dispatch](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/session.ts#L2483), [wire schema](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/protocol/src/messages.ts#L1545)). The validated handler receives only `{ paseo }`, with no original principal, native Session, UI surface or authenticated user-gesture proof ([plugin-process.ts:495](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/plugins/plugin-process.ts#L495)).

Admission grants owner permissions for valid daemon password/local credential, absent password, and the documented-in-source legacy credentialless relay branch ([session-admission-auth.ts](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/session-admission-auth.ts#L11)). Plugin IPC sockets receive owner admission independently ([websocket-server.ts:1016](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/websocket-server.ts#L1016)). **Inference:** authorized daemon clients can invoke registered RPCs; this route proves daemon authority, not human UI intent. An agent lacking `daemon.manage` cannot use this route; possession of owner credentials changes that premise.

Reserved plugin client IDs are checked against actual plugin socket attachment ([identity check](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/websocket-server.ts#L1599)). This identifies the plugin connection, not the originating UI caller. `useRpc`'s surface-context requirement is client-side ([rpc-context.tsx](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/plugin/src/client/rpc-context.tsx#L26)).

**Substantiated authority tradeoff:** `daemon.manage` also permits plugin installation/removal, daemon configuration reload and shutdown. It is broader than harness-command authority; the permission map establishes this without a live exploit claim.

## 3. Startup SDK acquisition

**Read:** server contribution receives registration methods, no `paseo`. The subprocess internally creates/connects an IPC-backed SDK **before** calling the contribution, but passes that SDK only to RPC/hook invocations ([contracts.ts](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/plugin/src/server/contracts.ts#L30), [initialization](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/plugins/plugin-process.ts#L259)). The [public lifecycle catalog](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/plugin/src/server/lifecycle.ts#L47) contains no plugin-start/ready callback. Internal reconnection reattaches the plugin's daemon socket ([runtime.ts:814](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/plugins/runtime.ts#L814)); it does not expose a setup accessor.

The supported standalone SDK requires an explicit URL and authentication when configured ([quickstart](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/public-docs/sdk/quickstart.md#L17)). **Gap:** no supported automatic startup acquisition from server setup was found. Waiting for an RPC/hook is event-triggered acquisition, not guaranteed startup reconciliation. No default port, undocumented configuration field or ambient credential is established here.

## 4. Versioned MCP requirements and identities

The [version catalog](https://modelcontextprotocol.io/docs/2026-07-28/learn/versioning) lists **2026-07-28** current; its [HTTP binding](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http#security--endpoint) removes protocol sessions and retains Origin validation/local binding/authentication requirements. No provider support for that revision is inferred.

For final **2025-11-25**, [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#security-warning) MUST validate Origin; present invalid Origin requires 403. Local servers SHOULD bind loopback and SHOULD authenticate connections: loopback alone does not defeat DNS rebinding. Its optional `MCP-Session-Id` is transport state; 404 requires reinitialization. [Security guidance](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices#session-hijacking) explicitly forbids using sessions as authentication. Neither wire ID nor client-supplied agent ID establishes the design's authenticated native Session/authority binding.

Paseo injects native `PASEO_AGENT_ID` into launch environment ([manager:5361](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/server/src/server/agent/agent-manager.ts#L5361)); the custom HTTP mappings above do not automatically authenticate that identity. `agent.create` hooks receive config/env; session-open hooks receive native agent ID but transform environment ([hook contracts](https://github.com/getpaseo/paseo/blob/cafe4b01c8522ff39560241c5deb01427dc8dc5b/packages/plugin/src/server/lifecycle.ts#L32)).

[Authorization 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization#protocol-requirements) is optional; HTTP implementations SHOULD follow its OAuth flow. Following it entails mandatory OAuth/resource metadata discovery, audience validation, authorization on every request, no query-string tokens, HTTPS authorization endpoints and PKCE for authorization-code clients. Localhost redirect permission is not a blanket OAuth exemption.

**Inference:** an explicitly nonstandard local pairing can use custom scoped per-Session bearers as a reasoned departure from that SHOULD ([RFC2119 §3](https://www.rfc-editor.org/rfc/rfc2119.html#section-3)); it cannot claim the complete standardized OAuth flow. Scoping/rotation remain application obligations. **Gaps:** native Session binding, actual negotiated revisions and Claude/Codex interoperability. No architecture is selected.
